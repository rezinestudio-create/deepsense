# Deepsense storefront

Static storefront plus Vercel Functions for the shared Owner Console state.

## Files that must be in the repo

- `index.html`, `style.css`, `storefront.js` — public site
- `assets/` — product images
- `api/store.js` — public catalog endpoint (`GET /api/store`)
- `api/owner.js` — owner endpoint (`POST /api/owner`)
- `api/health.js` — deployment check (`GET /api/health`)
- `lib/store.js` — Vercel Blob storage, password hashing, payload sanitizing
- `package.json`, `package-lock.json` — `@vercel/blob` dependency, ESM mode
- `.gitignore` — keeps `node_modules/` and env files out of the repo

`node_modules/` is generated by `npm install` and is ignored by Git.

## Deploy to Vercel

1. Create a new GitHub repo from this folder, then import it in Vercel. Make sure
   `api/` and `lib/` are at the **repo root** (not inside another subfolder), and that
   Vercel's **Root Directory** setting is blank / `.`.
2. In the Vercel project: **Storage → Create Storage → Blob**, private, connected to the project.
3. Add environment variable `OWNER_PASSWORD` (Production, Preview, Development).
4. Deploy. Framework preset can be left as **Other**; no build command is needed.
5. Open `/api/health`. It must return `{"ok":true,...}` before testing the Owner Console.

See `DEPLOYMENT.md` for propagation details and troubleshooting.

## Local development

```powershell
npm install
npx vercel env pull
npx vercel dev
```

A plain static server will not work because `/api/store` and `/api/owner` need the
Vercel Functions runtime.
